# Agent Catalog

All agent implementations for card-based Liar's Poker. Every agent is a
distinct named class in `agent/web/backend/agents.py` (Python) and mirrored
inline in `docs/index.html` (JavaScript).

**Rule**: Never silently repurpose an existing agent for a new game mode by
adding conditionals. Instead, add a new named class here so the catalog stays
accurate and old behaviour is preserved.

---

## Standard Rules (52-card deck, count-up or count-down)

### `BiasedRandomAgent(accept_prob)` — 4 named variants
- **Strategy**: Accepts (bids higher) with probability `accept_prob`; calls bluff with `1 - accept_prob`.
  When bidding, picks uniformly from the next up-to-5 legal bids in the partial order.
  On first bid (no current bid), always bids from the first 5 legal bids.
- **Variants**: `biased30` (30%), `biased40` (40%), `biased60` (60%), `biased70` (70%).
  The 50% counterpart is the existing `RandomAgent`.
- **Data**: None.
- **Modes**: All modes.
- **Use for**: Parameterised aggression benchmarks; exploitability measurement.

### `RandomAgent` — *"Coin Flip"*
- **Strategy**: Uniform random over all legal actions.
- **Data**: None.
- **Modes**: All modes (standard, exact, five-kings, high-hand).
- **Use for**: Baseline comparison; sanity testing.

### `BlindBaselineAgent`
- **Strategy**: 50% marginal threshold — bids the highest hand where
  P(pool ≥ bid | total cards = n) ≥ 0.5. Calls when standing bid exceeds
  the threshold.
- **Data**: `hand_rank_probs_matrix.json` (marginal MC, 3M samples, 52-card deck).
            Falls back to `blind_equilibrium.json` for n < 5.
- **Modes**: Standard rules only (count-up or count-down — same probabilities).
- **Note**: Ignores private cards entirely; good lower bound on strategic play.

### `ConditionalAgent`
- **Strategy**: Same threshold logic as BlindBaseline but adjusts the threshold
  upward when the private hand matches a strong condition (pair, trips, suited,
  etc.), using condition-specific conditional probability tables.
- **Data**: `extended_conditional_probs_ranked.json` (1M samples per condition,
            74 conditions × 21 pool sizes).
            Falls back to `BlindBaselineAgent` for n < 5 or n > 25.
- **Modes**: Standard rules only.
- **Note**: Best general-purpose agent for standard rules.

## Exact Hand Rules (52-card deck, bid must have exact 5-card subset in pool)

### `ExactRulesBlindAgent`  *(internal fallback — not exposed in UI)*
- **Strategy**: "Peak probability" — calls when the standing bid's
  `exact_prob[i]` is below 30% of the highest exact prob for this pool size.
  When bidding, picks the legal raise with the highest `exact_prob`.
  Uses `exact_prob[i]` = P(pool contains a 5-card subset with best hand
  exactly = bid_i | n), NOT the cumulative at-least table.
- **Data**: `exact_rules_probs.json` `["exact"]` key.
- **Modes**: Exact Hand Rules mode only.
- **Note**: Ignores private cards. Exposed only as a fallback; prefer
  `ExactRulesConditionalAgent`.

### `ExactRulesConditionalAgent`
- **Strategy** (5-fix version, 2026-04-22):
  1. **High Hand declaration**: when the standing bid has `exact_prob` in the
     top `hh_band` (default 15%) of live bids, emit `HH_ACTION` instead of
     calling bluff.
  2. **Smallest-safe raise**: always raises to the lowest legal bid whose
     adjusted exact prob ≥ `safety_frac × peak_adj_exact` (default 0.8×);
     prevents unnecessary escalation into improbable bids.
  3. **0.5-threshold call**: calls bluff when adjusted exact prob of the
     standing bid is below 0.5; previously used a raw exact-prob comparison
     that ignored private-hand adjustment.
  4. **Bayesian opponent-bid update**: when the opponent's last bid is known,
     multiplies adjusted probs for bids ≤ opp bid by `opp_bid_alpha` (default
     0.7) — they likely wouldn't bid below their belief.
  5. **Exact-rules conditional table preference**: when
     `extended_conditional_exact_probs.json` is available, loads it via
     `WarmStartLookup.get_exact_rules_conditional(n, cond_key)` and uses those
     tables directly instead of the likelihood-ratio approximation.
- **Data**:
  - `exact_rules_probs.json` `["exact"]` key (always required)
  - `extended_conditional_exact_probs.json` (preferred, generated by
    `compute_extended_conditional_exact_probs.py`; falls back to
    likelihood-ratio from `extended_conditional_probs_ranked.json` if missing)
- **Modes**: Exact Hand Rules mode only (with or without High Hand enabled).
- **Note**: `extended_conditional_exact_probs.json` was first generated
  2026-04-22 (70 conditions × 21 pool sizes, 10k samples/condition, ~4-6h).

## Five-Kings Mode (53-card deck, 5K Kings > SF)

### `FiveKingsBlindAgent`
- **Strategy**: Same 50% marginal threshold as BlindBaseline, calibrated for
  the 53-card deck.  Bid index 110 = Five of a Kind Kings is included in the
  probability table.
- **Data**: `five_kings_probs.json` (generated by `compute_five_kings_probs.py`,
            default 1M samples).
- **Modes**: Five-Kings easter egg mode only.
- **Availability**: Requires `five_kings_probs.json` to exist; falls back to
  `BlindBaselineAgent` (standard 52-card probabilities) if missing.

## Benchmark — Running / Updating

The Agent Zoo dashboard in `docs/index.html` shows head-to-head win rates from a pre-run benchmark.
To regenerate after adding new agents:

```bash
cd "Liars poker/"
python -m agent.benchmark --games 100 --seed 42
```

Output: `agent/data/benchmark_results.json`.
Then re-embed the JSON into the `BENCHMARK_RESULTS` constant in `docs/index.html` and update `AGENT_META`.

## Adding a New Agent — Checklist

1. Add the class to `agent/web/backend/agents.py` with a clear docstring naming
   what data it uses and what mode it targets.
2. Mirror the strategy in `docs/index.html` (JS) under `// 5. AGENTS`.
3. Add it to the setup dropdown in `renderSetup()` (JS) and the route handler
   in `agent/web/backend/app.py`.
4. Add an entry to this catalog with: strategy, data file, mode, fallback.
5. If it requires new MC data: add a `compute_*.py` script under `agent/data/`
   and add the file to the Data Files Summary table above.
